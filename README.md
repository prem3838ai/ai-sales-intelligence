# AI Sales Intelligence Platform

A portfolio project combining sales analytics, machine-learning-based revenue forecasting, and customer segmentation. Built with Python, Pandas, scikit-learn, Plotly, and Streamlit.

> **Data notice:** The included dataset is synthetic demo data generated by `scripts/generate_sample_data.py`. It is not real company data and must not be used to claim real-world business performance.

## Features

- Sales KPIs: revenue, orders, unique customers, average order value, and profit
- Date filtering and daily revenue trends
- Revenue by category and top products
- Naive weekly baseline vs. Random Forest forecasting with chronological holdout evaluation
- Customer RFM features and K-Means segments
- CSV exports for forecasts, customer segments, and filtered transactions
- Input validation and automated tests

## Tech stack

- Python, Pandas, NumPy
- scikit-learn: Random Forest, StandardScaler, K-Means
- Streamlit and Plotly
- pytest
- SQLite persistence layer using Python's built-in `sqlite3` module

## Architecture

```text
CSV --> scripts/import_to_sqlite.py --> SQLite database
                                      |
                                      v
src/database.py --> SQL queries + derived revenue/profit
        |
        |
        v
src/analytics.py ---> KPIs, daily sales, RFM segments
src/forecasting.py -> baseline, ML evaluation, future predictions
        |
        v
app.py ---> Streamlit UI + Plotly charts + CSV downloads
```

## Forecasting methodology

The forecasting page uses a chronological holdout: the final selected number of days are reserved for evaluation. A Random Forest regressor uses lagged revenue and calendar features. The baseline predicts revenue using the value from seven days earlier. Mean Absolute Error (MAE) is reported for both models.

The included dataset is synthetic. Results are for demonstrating the workflow only. For a serious evaluation, use a documented real dataset, preserve time ordering, compare multiple rolling-origin splits, and assess whether the model beats a simple baseline consistently.

## Customer segmentation

Customers are summarized using:
- **Recency:** days since last purchase in the selected dataset
- **Frequency:** number of unique orders
- **Monetary:** total revenue attributed to the customer

Features are scaled before K-Means clustering. Segment names are descriptive labels based on cluster spend ranking, not validated business personas. Review cluster profiles before using them for business decisions.

## Data schema

| Column | Meaning |
|---|---|
| `order_id` | Unique transaction/order identifier |
| `order_date` | Order date |
| `customer_id` | Customer identifier |
| `product` | Product name |
| `category` | Product category |
| `quantity` | Units sold |
| `unit_price` | Selling price per unit |
| `unit_cost` | Cost per unit |

Revenue = quantity × unit price. Profit = quantity × (unit price − unit cost).

## Near-real-time transaction API

The sidebar form writes transactions to SQLite immediately. To accept transactions from another app or an authorized point-of-sale integration, run the included FastAPI service in a second terminal:

```bash
uvicorn api:app --reload
```

- Interactive API documentation: `http://127.0.0.1:8000/docs`
- Health check: `GET http://127.0.0.1:8000/health`
- Aggregate metrics: `GET http://127.0.0.1:8000/metrics`
- Recent transactions: `GET http://127.0.0.1:8000/sales?limit=100`
- Ingest transaction: `POST http://127.0.0.1:8000/sales`

Example JSON for `POST /sales`:

```json
{
  "order_id": "LIVE-0001",
  "order_date": "2026-10-25",
  "customer_id": "C-100",
  "product": "Keyboard",
  "category": "Electronics",
  "quantity": 2,
  "unit_price": 49.99,
  "unit_cost": 27.0
}
```

**Production warning:** This API is intended for local portfolio demos. Before public deployment, add authentication, request rate limits, audit logging, webhook signature verification, and a managed database. Do not expose unauthenticated write endpoints to the public internet.

## Public real-world dataset

Use the [UCI Online Retail dataset](https://archive.ics.uci.edu/dataset/352/online+retail) as the documented real-world analysis source. It contains invoice dates, product descriptions, quantities, unit prices and customer IDs. Create a preprocessing step to map those fields into this app's canonical columns; assign `Uncategorized` if category is unavailable. Unit cost is not included in the standard dataset, so profit is not valid for that source unless you obtain cost data separately. Check the dataset's current terms and cite the source in the repository before redistributing it. The bundled `data/sales.csv` remains synthetic demo data.

## Deployment path

1. Push this repository to GitHub.
2. Deploy `app.py` on [Streamlit Community Cloud](https://streamlit.io/cloud) for the dashboard.
3. Deploy the FastAPI service separately on a Python host such as [Render](https://render.com/); configure persistent storage or managed PostgreSQL.
4. Set `DATABASE_PATH` consistently for the API service. If the dashboard and API are deployed separately, they must share a supported database to see the same transactions; local SQLite files are not automatically shared across separate hosts.
